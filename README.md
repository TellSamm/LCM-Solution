# LCM Solution: резервная одометрия беспилотного трамвая по модели

Наше решение кейса «Резервная одометрия по модели» Хакатона Московского транспорта.
Команда LCM Solution: Семён Черников, Константин Муравьёв.

Задача: оценивать скорость и положение трамвая без GNSS и IMU, только по положению ручки контроллера
водителя и скоростям вращения колёс двух тележек, и публиковать результат в реальном времени в ROS 2 Humble.

## Что получилось

| Показатель (50 прогонов трамвая 30618, 36 часов записей, сравнение с GNSS-эталоном) | Значение |
|---|---|
| RMSE скорости | 0.03 м/с, систематического смещения нет |
| Средняя ошибка положения на прогоне 5.4 км | 8.7 м (медиана по прогонам) |
| Накопленный дрейф в конце прогона | 0.30 % дистанции |
| Частота публикации, задержка вход - выход | 39 Гц, 0.4 мс (пик 1.5 мс) |
| Ресурсы ноды | около 10 % одного ядра, 59 МБ памяти |
| Судья организаторов на их тестовом bag вне обучающей выборки | скорость RMSE 0.052 м/с, положение 3D RMSE 8.4 м, в их же контейнере check-code |

Цифры получены двумя независимыми способами: офлайн на всех прогонах и в настоящем ROS 2 внутри Docker
с воспроизведением bag в реальном времени, на arm64 и на x86_64. Подробности и графики в разделе о точности.

## Как проверить

Нужен только Docker. Готовый образ лежит в реестре GitHub, собирать ничего не нужно.

```bash
git clone https://github.com/TellSamm/LCM-Solution.git && cd LCM-Solution
./run.sh judge ПУТЬ_К_ПРОГОНУ        # Linux/macOS; Windows: .\run.ps1 judge C:\...\30618_0e41eac3
```

`ПУТЬ_К_ПРОГОНУ` - папка одного bag-прогона на вашем диске, в ней лежат `*_0.db3` и `metadata.yaml`.
Скрипт скачает образ, запустит ноду, воспроизведёт bag в реальном времени, запишет `/result/*`
и напечатает таблицу: требования против измеренного, точность относительно GNSS-эталона, CPU и память.
Все варианты запуска, ручной режим и сборка без Docker описаны в [инструкции для жюри](docs/JURY_INSTRUCTIONS.md).

## Как это работает

Трамвай едет по рельсу, поэтому задача одномерная: нужна скорость вдоль пути и пройденная дистанция,
а карта переводит дистанцию в координаты.

```
контроллер n   -> таблица ускорения a(n, v) + уклон и кривизна карты -> 1-D фильтр Калмана (v) -> интеграл -> s -> кольцевая карта -> x, y, z, курс
колёса f, r    -> масштаб -> валидация (слип, юз, зависание, выброс) -/
GNSS (только первые секунды) -> стартовая точка и направление
```

- Модель тяги. Мы не знаем ни момент двигателя, ни массу с пассажирами, но их отношение, удельное ускорение,
  наблюдается напрямую. Поэтому идентифицировали таблицу a(позиция контроллера, скорость), 31 на 16 ячеек,
  по медианам измеренного ускорения на 36 часах записей, отдельно для каждого трамвая. Уклон и кривизна берутся из карты.
- Фильтр. Одномерный Калман по скорости: предсказание по модели, коррекция по колёсам обеих тележек.
  Ворота по невязке отбраковывают слип и юз, детектор повторов ловит зависший датчик. Пока измерения недостоверны,
  ведёт модель, после аномалии одометрия перезахватывается сама.
- Карта. Pathgraph организаторов покрывает только перегон, а трамвай около 20 % времени проводит на разворотных
  петлях конечных, где стартует и финиширует каждый прогон. Петли мы восстановили офлайн из GNSS-треков обучающих
  записей и замкнули маршрут в кольцо с шагом 1 м, высотой, курсом, кривизной и уклоном.

Что мы нашли в данных по дороге: из 122 bag-файлов уникальных 97, ещё 35 без GNSS; датчики колёс отдают км/ч,
а не м/с, как написано в README датасета; масштаб колёс между датами записей плывёт до 1 %, это 50 м на круге.

## Структура репозитория

```
ros2_ws/src/tram_odometry/     пакет ROS 2 (ament_python)
  tram_odometry/estimator.py   ядро: фильтр, отбраковка, интегрирование; без ROS, поэтому тестируется офлайн
  tram_odometry/traction.py    модель тяги: таблица плюс уклон и кривизна
  tram_odometry/trackmap.py    карта пути: проекция дистанции в координаты, локализация старта
  tram_odometry/node.py        нода ROS 2: подписки, публикации, диагностика, замер задержки
  assets/                      track_ring.json и калибровки calib_30618 / calib_30639 / calib_default
  config/params.yaml, launch/odometry.launch.py
ros2_ws/src/tram_vehicle_msgs/ сообщения организаторов; добавили поле maintainer, без него colcon не собирает пакет
docker/                        Dockerfile на базе ros:humble-ros-base, entrypoint, профиль DDS
run.sh, run.ps1                запуск одной командой
tools/                         офлайн-конвейер: кэш bag, калибровка, карта, оценка, графики; judge_run.sh и
                               eval_recorded.py работают внутри контейнера
docs/                          документация и графики
```

Офлайн-конвейер воспроизводится по шагам, описанным в [`tools/README.md`](tools/README.md).
