# Ограничения решения и план развития после хакатона

## 1. Что решение делает хорошо
- Скорость: RMSE 0.04-0.07 м/с относительно GNSS на 67 прогонах (36 ч), без систематического смещения; переходные
  режимы (разгон, торможение, остановки) отслеживаются без запаздывания.
- Положение: медианная ошибка 11 м, дрейф в конце прогона 0.4 % от дистанции (5.4 км), включая разворотные петли,
  которых нет в pathgraph.
- Устойчивость: слипы, юз с блокировкой колёс, выбросы, зависание одного или обоих датчиков, пропадание колёсных
  сообщений до 10 с - без всплесков ошибки и без расходимости; после аномалии оценка восстанавливается автоматически.
- Реальное время: ~40 Гц публикации, задержка вход->выход 0.4 мс (пик < 5 мс), ~5-10 % одного ядра, 60 МБ ОЗУ.

## 2. Ограничения (честно)

| Ограничение | Влияние | Причина |
|---|---|---|
| Масштаб одометрии фиксирован на прогон | дрейф 0.1-1 % дистанции (5-50 м на круг) | эффективный радиус колеса меняется между датами до 1 %, без внешнего эталона он ненаблюдаем |
| Стартовая точка вне карты | смещение по дуге 10-50 м на весь прогон (25 % обучающих прогонов) | у Таллинской несколько параллельных путей/платформ, в карте один |
| Заезды вне маршрута (депо, служебные ветки) | положение «ползёт» по карте, пока трамвай вне неё | карта покрывает один маршрут (по условию кейса маршрут един) |
| Без GNSS на старте - только конфигурируемая точка | если трамвай стартует не оттуда - ошибка на всю длину прогона | без внешней привязки стартовое положение принципиально ненаблюдаемо |
| Модель тяги - табличная удельная, не силовая | при резком изменении массы (полный салон) модельное ускорение отклоняется на ~10 % | масса не измеряется; в основном контуре одометрия компенсирует |
| Одновременное зависание датчиков при равномерном ходе | не обнаруживается | неотличимо от нормы и безвредно для оценки |

## 3. План развития

### Ближний горизонт (недели)
1. **Онлайн-оценка масштаба колёс** по модельному ускорению на длинных участках выбега и служебного торможения
   (там модель наиболее точна) - сведение дрейфа к 0.1 %. Альтернатива - калибровка масштаба на первых метрах после
   старта, пока GNSS ещё доступен, с сохранением между прогонами.
2. **Расширение карты**: все платформы конечных, депо и служебные ветки; граф путей с выбором ветки по поведению
   (стоянка, кривизна, уклон) - устраняет ошибку стартовой точки.
3. **Автодетект трамвая** по статистике датчиков (шум задней тележки, отклик привода) вместо параметра `tram_id`.
4. **Адаптивная таблица тяги**: онлайн-дообучение ячеек $a(n,v)$ рекурсивным МНК по одометрии, пока она достоверна
   (модель «учится» у одометрии в норме и заменяет её при аномалиях).
5. Юнит-тесты и CI (сборка colcon, прогон на коротком бэге, проверка контракта топиков).

### Средний горизонт (месяцы)
6. **Силовая модель** $M(n,\omega)$ + оценка массы: наблюдатель массы по соотношению ускорения и позиции контроллера на
   разгонах (масса пассажиров - медленная переменная, оценивается за 1-2 разгона).
7. **Слияние с внешними датчиками при их наличии**: та же архитектура (1-D фильтр вдоль пути) принимает GNSS/лидарную
   локализацию как редкие коррекции $s$; при отказе продолжает работать - резервный канал становится основным контуром
   локализации вдоль пути.
8. **Детектор сцепления**: оценка коэффициента сцепления по рассогласованию тележек и модельному моменту -> сигнал для
   системы управления тягой/торможением (антиюз, антибуксование) и для прогноза тормозного пути.
9. Перенос на C++ (rclcpp) для детерминированных задержек на бортовом вычислителе; текущая Python-реализация
   укладывается в требования с запасом в 20 раз, поэтому не приоритет.

### Интеграция в контур беспилотного трамвая
- Выход `nav_msgs/Odometry` с ковариацией -> напрямую в EKF локализации (robot_localization / Autoware) как источник
  продольной скорости и положения при отказе GNSS.
- `/result/diagnostics` -> мониторинг состояния датчиков колёс (зависание, слип) для системы диагностики.
- Карта пути и калибровки - версионируемые артефакты, обновляемые по накопленным прогонам без изменения кода.
