## Поле 1. Ссылка на пакет(ы) ROS 2 Humble

https://github.com/TellSamm/LCM-Solution

Пакет `tram_odometry` (Python, ament_python): `ros2_ws/src/tram_odometry`. Пакет сообщений организаторов
`tram_vehicle_msgs`: `ros2_ws/src/tram_vehicle_msgs` (добавлено обязательное поле `<maintainer>` в package.xml — без него
colcon build завершается ошибкой; определения сообщений не изменялись). Сборка стандартным `colcon build` (Dockerfile:
`docker/Dockerfile`, база `ros:humble-ros-base`, x86_64 и arm64). Подписки: `/vehicle/front_bogie_velocity`,
`/vehicle/rear_bogie_velocity`, `/vehicle/driver_position_cmd`; GNSS-топики — только первые 5 с для начальной выставки.
Публикация: `/result/velocity` (tram_vehicle_msgs/VelocitySensor, м/с), `/result/position` (nav_msgs/Odometry),
дополнительно `/result/diagnostics` (флаг проскальзывания, статусы датчиков, σ). Запуск:
`ros2 launch tram_odometry odometry.launch.py` (по умолчанию калибровка трамвая 30618; `tram_id:=30639` — лаборатория).

## Поле 2. Ссылка на инструкцию для жюри

https://github.com/TellSamm/LCM-Solution/blob/main/docs/JURY_INSTRUCTIONS.md

Проверка одной командой в Docker: `bash /tools/judge_run.sh /data/<bag> 30618` — запускает ноду, воспроизводит bag в
реальном времени, записывает `/result/*` в rosbag2, считает метрики относительно GNSS-эталона из того же bag (RMSE/MAE/bias
скорости, ошибка положения mean/median/RMSE/max, финальная ошибка и дрейф в %) и печатает CPU/ОЗУ ноды. Ручной режим
(`ros2 topic hz/echo`), просмотр задержки (лог ноды каждые 10 с: частота, средняя и пиковая задержка вход→публикация),
команды для Linux/macOS/Windows и нативная сборка без Docker — в инструкции.

## Поле 3. Описание математической модели

https://github.com/TellSamm/LCM-Solution/blob/main/docs/MODEL.md

Кратко: нелинейная модель тягового привода и продольной динамики в форме удельного ускорения a(n, v) (31 позиция
контроллера × 16 интервалов скорости), идентифицированного по медианам измеренного ускорения на 36 ч обучающих прогонов,
отдельно для двух трамваев; плюс уклон и кривизна из карты пути. Скорость — одномерный фильтр Калмана: предсказание по
модели, коррекция по одометрии двух тележек с воротами по невязке (слип/юз/выброс) и детектором зависания датчика.
Положение — интеграл скорости, спроецированный на кольцевую карту маршрута (pathgraph организаторов + разворотные петли
конечных, восстановленные из GNSS-треков) в системе координат эталона (UTM 37N со смещением). Начальная выставка — по
двум GNSS-антеннам в первые секунды (положение base_link и направление), без GNSS — из конфигурируемой точки.

## Поле 4. Допущения, ограничения, конфигурируемые параметры

https://github.com/TellSamm/LCM-Solution/blob/main/docs/ASSUMPTIONS_AND_PARAMETERS.md

Ключевые допущения: движение по известному маршруту (карта), датчики колёс в км/ч, постоянный масштаб одометрии в
пределах прогона, GNSS только для стартовой точки. Параметры (`config/params.yaml`, launch-аргументы): `tram_id`
(калибровка 30618/30639/усреднённая), `default_start` (стартовая точка без GNSS), окно GNSS-выставки, шумы фильтра
(`q_accel`, `r_wheel`), ворота (`gate_sigma`, `gate_min`), пороги зависания, таймаут перезахвата, адаптивный шум, длина
перекрываемого пропуска, частота публикации. Калибровка трамвая (`assets/calib_<id>.yaml`): масштабы колёс, таблица тяги,
коэффициент сопротивления в кривых; уклон — из карты.

## Поле 5. Сведения о точности и быстродействии

https://github.com/TellSamm/LCM-Solution/blob/main/docs/ACCURACY_AND_PERFORMANCE.md

Методика: сопоставление с GNSS-эталоном (base_link по двум антеннам) по ближайшей метке времени в пределах 0.05 с, как у
судьи. 67 уникальных прогонов с GNSS (36 ч, ~360 км): RMSE скорости 0.03 м/с (медиана, трамвай 30618), без смещения; средняя
ошибка положения 8.7 м (30618, медиана по прогонам), дрейф в конце прогона 0.3 % дистанции. Устойчивость: синтетические
зависания датчиков (одного и обоих), юз, слип, выбросы, пропадание входов до 10 с — без роста ошибки и без расходимости.
Реальное время (Docker, `--cpus=2 --memory=512m`, `ros2 bag play --rate 1.0`, 22 мин): 39 Гц, задержка вход→публикация
0.5 мс (пик 1.6 мс), ~10 % одного ядра, 59 МБ ОЗУ без роста. Графики и таблицы — в документе; лог прогона приложен.

## Поле 6. Ограничения решения и план развития

https://github.com/TellSamm/LCM-Solution/blob/main/docs/LIMITATIONS_AND_ROADMAP.md

Ограничения: масштаб колёс не адаптируется онлайн (дрейф 0.1–1 % при смене эффективного радиуса); стартовая точка вне
карты даёт смещение по дуге; заезды вне маршрута (депо) картой не покрыты; модель тяги — табличная удельная, без явной
массы. План: онлайн-оценка масштаба по модели на выбеге, граф путей со всеми платформами и ветками, автодетект трамвая,
онлайн-дообучение таблицы тяги, наблюдатель массы, интеграция как источник Odometry в EKF локализации беспилотного
контура, детектор сцепления для антиюза, перенос на C++.
